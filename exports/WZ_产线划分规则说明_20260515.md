# WZ 产线划分规则说明

生成日期：2026-05-15

适用范围：`WZ_ProductionOutputDetail` 明细归属产线，以及由明细重算 `WZ_ProductionOutput` 的产能统计。

## 1. 总体口径

产线归属按明细行处理，不直接按汇总格子倒推。每一条订单明细会先生成唯一业务键，去重后再判断阀门类别和产线。

汇总口径为：

```text
运算日期/排产日期 × 阀门类别 × 产线 = 数量合计
```

只有已经明确归属的明细才参与汇总。当前可汇总状态包括：

- `matched`：ESB 原始数据本身已有明确阀门类别和产线。
- `matched_order_cycle`：通过 `WZ_OrderCycleBase` 或原始产线规范化补齐。
- `matched_sync_line`：同步物料字段中存在可识别的真实产线时补齐。
- `matched_rule`：通过 10.11.10.101 规则服务推断补齐。

以下状态不进入产能汇总：

- `missing_line`：没有足够信息确定产线。
- `conflict`：同一业务键出现多个候选产线，且无法消解。

## 2. 数据来源优先级

空产线或冲突行按以下顺序补齐：

1. `WZ_OrderCycleBase`
   - 优先按 `FENTRYID` 找订单周期基础表。
   - 找不到时，再按 `销售订单号 + 计划跟踪号` 匹配。
   - 若表内已有 `AssignedProductionLine`，直接采用。
   - 若只有 `ProductionLine`，则走本地规范化规则生成 `AssignedProductionLine`。

2. `ERP_OrderTracking + OCP_Material`
   - 用订单跟踪表关联物料主数据，补齐阀门类别、产品名称、规格型号、通径、压力、材质等字段。
   - 再调用规则服务推断产线。

3. `OCP_OrderTracking + OCP_Material`
   - 这是本次补数据后的关键兜底来源。
   - 通过 `SOBillNo + MtoNo` 对应销售订单和计划跟踪号。
   - 用物料字段组装规则服务请求。
   - `OCP_OrderTracking` 本身没有真实产线字段；`OCP_Material.Workshop` 当前多数是“装配车间”，不能直接当作产线。只有值以“旋转/直通/蝶阀”开头且不含“车间”时，才作为同步产线候选。

4. 10.11.10.101 规则服务 `/batch_infer`
   - 返回 `sheng_chan_xian` 后，再走本地规范化规则，生成最终归属产线。

## 3. 阀门类别补齐规则

当明细缺少阀门类别时，会用物料规格型号和产品名称补齐。规则入口：

```text
ValveCategoryRuleJudge.TryJudgeBySpecOrProduct(specModel, productName)
```

### 3.1 规格型号特殊规则优先

如果规格型号命中特殊规则，优先于产品名称：

| 规格/型号 | 阀门类别 |
| --- | --- |
| `H41H-16C` | 软密封球阀 |
| `H41H-16P` | 软密封球阀 |
| `H420-T` | 软密封球阀 |
| `H44Y-10P` | 软密封球阀 |
| `R1/4闸阀（小球阀）` | 软密封球阀 |
| `RC1/4小球阀` | 软密封球阀 |
| `REM` | 软密封球阀 |
| `VFR` 或 `VFR*` | 硬密封球阀 |
| `JVBJG` | 蝶阀 |

### 3.2 产品名称前缀规则

规格型号没有命中特殊规则时，根据产品名称判断：

| 产品名称规则 | 阀门类别 |
| --- | --- |
| `ZJHQR*` | 软密封球阀 |
| `ZJHRF*` | 软密封球阀 |
| `ZJHVF*` | 软密封球阀 |
| `ZJHV*` | 硬密封球阀 |
| `ZZ*` | 直通阀 |
| `V*` | 蝶阀 |
| `K*` | 直通阀 |
| `P*`、`Q*`、`T*` | 软密封球阀 |
| `J*` | 软密封球阀 |
| `H*` | 直通阀 |
| `R*` | 硬密封球阀 |
| `Z*`，但不是 `ZZ*` 或 `ZJH*` | 软密封球阀 |

### 3.3 ZJHR 数字段规则

产品名称为 `ZJHR-数字...` 时，按数字判断：

| 数字集合 | 阀门类别 |
| --- | --- |
| `1000, 1001, 1003, 1010, 1011, 2000, 2010, 4000, 4010` | 软密封球阀 |
| `1100, 1101, 1110, 1111, 1113, 2100, 2110, 3110, 3111, 4100, 3` | 硬密封球阀 |
| 其他数字或无法识别 | 硬密封球阀 |

以下产品名称不自动补阀门类别：


## 4. 原始产线规范化规则

本地会把原始 `ProductionLine` 转成最终 `AssignedProductionLine`。规则入口：

```text
WZ_OrderCycleBaseService.CalcAssignedProductionLine(productionLine, valveCategory, nominalDiameter)
```

### 4.1 蝶阀

条件：

```text
ProductionLine 以“旋转”开头
ValveCategory = 蝶阀
```

按公称通径划分：

| 公称通径 | 最终产线 |
| --- | --- |
| `DN50, DN65, DN80, DN100, DN125, DN150` | 蝶阀1 |
| `DN200, DN250, DN300` | 蝶阀2 |
| `DN350, DN400, DN450, DN500, DN600` | 蝶阀3 |
| 其他通径 | 蝶阀4 |

注意：当前代码中 `DN100` 同时出现在第一组和第二组配置里，但判断顺序先判断第一组，因此实际归属为 `蝶阀1`。

### 4.2 直通类

条件：

```text
ValveCategory 以“直通”开头
```

处理：

```text
最终产线 = 原始 ProductionLine 去空格后的值
```

### 4.3 软密封球阀

条件：

```text
ProductionLine ∈ 旋转1, 旋转2, 旋转3, 旋转4, 旋转5
ValveCategory = 软密封球阀
```

处理：

```text
最终产线 = 原始 ProductionLine + "A"
```

例如：

| 原始产线 | 最终产线 |
| --- | --- |
| 旋转1 | 旋转1A |
| 旋转2 | 旋转2A |
| 旋转3 | 旋转3A |
| 旋转4 | 旋转4A |
| 旋转5 | 旋转5A |

### 4.4 其他情况

如果不满足以上规则，且没有已有 `AssignedProductionLine`，则不强行归属，保留为异常明细。

## 5. 10.11.10.101 规则服务匹配规则

服务地址：

```text
POST http://10.11.10.101:8000/batch_infer
```

规则来源：

```text
MySQL valve_rule_db.valve_rule
```

有效规则必须同时满足：

```text
sheng_chan_xian 不为空
gu_ding_zhou_qi 不为空
```

### 5.1 参与匹配的字段

规则服务使用以下字段：

```text
fa_men_da_lei          阀门大类
fa_men_lei_bie         阀门类别
chan_pin_ming_cheng    产品名称
gong_cheng_tong_jing   工程通径
gong_cheng_ya_li       工程压力
fa_ti_cai_zhi          阀体材质
nei_jian_cai_zhi       内件材质
mi_feng_mian_xing_shi  密封面形式
fa_lan_lian_jie        法兰连接
shang_gai_xing_shi     上盖形式
liu_liang_te_xing      流量特性
zhi_xing_ji_gou        执行机构
fu_jian_pei_zhi        附件配置
wai_gou_fa_ti          外购阀体
wai_gou_biao_zhi       外购标志
te_pin                 特品
xu_hao                 序号
```

### 5.2 匹配过程

规则服务先做向量召回，再按字段组逐级精确过滤；如果向量召回无法定案，会回退到全量规则精确扫描。

本地调用顺序：

1. 优先把 `OCP_Material.SpecModel` 传入 `chan_pin_ming_cheng`。
2. 如果规格型号未命中，且 `OCP_Material.ProductModel` 非空并且不同于规格型号，则用产品型号再兜底调用一次。
3. 不把本地按前缀推断出的阀门类别强行传给规则服务。实测部分型号在只传产品型号、通径、压力时能唯一命中；额外传本地推断类别反而可能触发 `NO_MATCH`。
4. 规则服务返回产线后，本地再用规格型号/产品型号补齐阀门类别，并执行蝶阀、直通、软密封球阀的产线规范化。

过滤顺序：

1. 阀门大类、阀门类别、产品名称
2. 工程通径、工程压力
3. 阀体材质、内件材质
4. 特品、外购标志、外购阀体
5. 执行机构、附件配置
6. 法兰连接、上盖形式、流量特性、密封面形式

字段比较前会做标准化：

```text
去空格、转小写、空值忽略
```

某一轮过滤后，如果剩余规则的 `(sheng_chan_xian, gu_ding_zhou_qi)` 已经唯一，就定案返回。

### 5.3 异常处理

| 返回原因 | 含义 | 本地处理 |
| --- | --- | --- |
| `NO_RULE_FIELDS` | 请求没有任何规则字段 | 不归属 |
| `NO_MATCH` | 字段组合没有匹配规则 | 不归属 |
| `AMBIGUOUS` | 匹配到多组不同产线/周期 | 不归属，避免错分 |
| 服务异常 | 规则服务不可用或返回异常 | 不归属，记录日志 |

## 6. 最终汇总规则

补齐完成后，按以下条件重建汇总表：

```sql
ClassifyStatus IN (N'matched', N'matched_order_cycle', N'matched_sync_line', N'matched_rule')
AND ValveCategory <> N''
AND ProductionLine <> N''
```

聚合维度：

```text
ProductionDate, ValveCategory, ProductionLine
```

阈值来自：

```text
WZ_ProductionOutputThreshold.ValveCategory + ProductionLine
```

超阈值判断：

```text
Quantity > CurrentThreshold
```

## 8. 当前风险点

1. `WZ_OrderCycleBase` 如果未初始化或数据缺失，只能依赖 `OCP_OrderTracking + OCP_Material + 规则服务` 兜底。
2. 规则服务只有在字段足够且结果唯一时才返回产线；字段缺失或规则库冲突时不会强行分配。
3. `DN100` 当前实际进入 `蝶阀1`，如果业务期望进入 `蝶阀2`，需要调整配置顺序或去掉重复项。
4. 规则服务每次 `/batch_infer` 都会写日志，批量验证时需要控制批量大小和日志清理策略。

## 9. 本次性能与可观测性优化

### 9.1 明细入库性能

`WZ_ProductionOutputDetail` 入库从逐行 `MERGE` 改为：

```text
DataTable -> SqlBulkCopy -> SQL Server 临时表 -> 一次 MERGE
```

这样全量刷新时不再对几十万明细逐行发 SQL，事务口径保持不变：先写明细，再重建 `WZ_ProductionOutput` 汇总。

### 9.2 规则服务调用去重与缓存

同一次刷新内，规则服务请求会按以下字段生成指纹并缓存：

```text
产品文本模式 + 阀门类别/大类 + 产品文本 + 通径 + 压力 + 材质 + 连接 + 上盖 + 流量特性 + 执行机构 + 附件 + 密封面等规则字段
```

同指纹只请求一次 10.11.10.101。成功结果复用到同指纹明细；失败结果也缓存，避免重复打规则服务和重复写规则服务日志。

### 9.3 未归属明细记录

剩余无法唯一分线的行不再扩展兜底猜测，保持：

```text
ClassifyStatus = missing_line 或 conflict
```

这些行保留在 `WZ_ProductionOutputDetail`，但不进入 `WZ_ProductionOutput` 汇总。刷新日志会记录未归属总数、按订单 Top、按排产日期 Top 和样例。

### 9.4 同步健康检查

新增接口：

```text
GET /api/WZ/ProductionOutput/sync-health?start=2026-07-01&end=2026-07-31
```

返回内容包括：

- 明细总行数、可汇总行数、未归属行数、冲突行数。
- 明细最近 `LastSyncTime`。
- `OCP_OrderTracking` 最近 `ESBModifyDate` 和 `ModifyDate`。
- 指定排产日期范围内的 OCP 行数。
- 未归属明细按订单、按日期的 Top 分布。
- 未归属样例明细，便于人工判断是否需要补规则。

## 10. `/api/WZ_OrderCycleBase` 产能排产优化日期规则

`calculate-capacity-schedule-date` 当前按以下口径计算 `CapacityScheduleDate`：

1. 计算闭区间为 `StandardDeliveryDate` 到 `ReplyDeliveryDate`，缺少任一日期或 `ReplyDeliveryDate < StandardDeliveryDate` 时不写入优化日期。
2. 若 `ScheduleDate` 落在该闭区间内，且当天 `Quantity + OrderQty <= CurrentThreshold`，直接排当天，`CapacityScheduleDate = ScheduleDate`。
3. 若当天不能直接排，则在闭区间内依次尝试：
   - 正常日产能：`Quantity + OrderQty <= CurrentThreshold`
   - 日预留产能：非周六日期，`Quantity + OrderQty <= CurrentThreshold * 120%`
   - 周六预留产能：周六日期，`Quantity + OrderQty <= CurrentThreshold * 120%`
4. 若以上都超过 120%，则只在该闭区间内选择排后负载率最低的日期进行均匀摊排，负载率按 `(Quantity + OrderQty) / CurrentThreshold` 计算。
5. 阈值来源优先级：
   - 优先取 `WZ_ProductionOutputThreshold` 中同 `ValveCategory + ProductionLine` 的 `CurrentThreshold`
   - 取不到时，回退到现有 `WZ_ProductionOutput` 中同 `ValveCategory + ProductionLine` 的 `CurrentThreshold`
   - 两处都取不到或未命中产能数据时，若 `ScheduleDate` 存在，则按 `CapacityScheduleDate = ScheduleDate` 兜底补齐
6. 计算结束后会再次补扫 `WZ_OrderCycleBase`，凡 `ScheduleDate` 存在且 `CapacityScheduleDate` 仍为空的记录，都按排产日期补齐排产优化日期。
